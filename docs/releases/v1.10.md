This release moves the org secret scan to betterleaks 2.0.0-rc.10, whose default rules changed, and fixes a fail-open path in the legacy architect-review gate: a candidate PR that was armed for auto-merge and then pushed to stayed armed (#709). The verifier's rules for consumers are unchanged. The images it accompanies ship tofu 1.13.10, npm 12.2.3, uv 0.13.9, CPython 3.15.2 build 20261123 and betterleaks 2.0.0-rc.10, and no longer have the base layer's `pebble` binary on their filesystem.

**Tag:** `v1.10`, on the commit this Release page shows. Pin the reusable workflows to that commit's full SHA, never to the tag name: each called workflow checks that it was pinned by SHA. The tag is created by the release workflow's App and is not GPG-signed. The consumer lint (`tools/check-consumer-workflows.sh`) and this repo's `tools/check-self-pins.sh` check that a pin's `# vX.Y` comment names a tag that peels to the pinned commit.

## Upgrade

The template files at this tag still pin `v1.9`, because a commit cannot pin its own release. Use the tag's commit SHA, or copy the template from the pin-bump PR that follows this release. The template's `.devcontainer/Dockerfile` line 1 is already dockerfile 1.29, which the `v1.10` verifier allows, as `v1.9`'s did.

### First: expect new secret-scan findings

The org secret scan reads its betterleaks version from this repo at the caller's pin, so re-pinning `secret-scan.yml` to `v1.10` moves a repo's `secrets / scan` from 2.0.0-rc.8 to 2.0.0-rc.10. betterleaks rc.9 and rc.10 change the default rules: new and widened detectors, decoding of padded URL-safe and unpadded standard base64, and entropy filtering on by default. The org rule set in this repo is unchanged, and this repo's own full-history scan passes on rc.10, but a consuming repo's results can change in either direction. The scan covers the full ancestry of the PR head, so a new finding can sit in an old commit.

Keep the `secret-scan.yml` re-pin out of a grouped Dependabot PR, so that its `secrets / scan` result is read on its own before it merges. A repo's pre-commit hook moves to rc.10 separately, when the repo takes an image digest built after #700, which can come before or after the re-pin.

### Every consuming repo

1. **Re-point the pins** to `@<full SHA of the v1.10 tag's commit> # v1.10`. Dependabot's `github-actions` ecosystem proposes this as a reviewed PR.
   - `devcontainer-image.yml`: the verifier. Its rules for consumers are unchanged since `v1.9` (below).
   - `secret-scan.yml`: the scanner moves to betterleaks 2.0.0-rc.10, as above.
   - Legacy-gate repos only: `devcontainer-bump-decision.yml` in the gate's `decide` job. Keep it on the same SHA as the verify pin, or the consumer lint warns.
2. **Legacy-gate repos: re-copy the gate.** `template/.github/workflows/architect-review-gate.yml` changed in its `post` job (behaviour changes, below). Re-copy it from the pin-bump PR that follows this release, keeping the repo's own `CONSUMER` blocks, so the copy and its `decide` pin move together.
3. **Re-run the consumer lint** from a checkout of this repo at `v1.10`: `<checkout>/tools/check-consumer-workflows.sh <your-repo>/.github/workflows`. Its rules are unchanged since `v1.9`.

A repo pinned to a release older than `v1.9` also takes the upgrade steps in the notes of each release it skips: for example `v1.9`'s retirement of dockerfile 1.27 on line 1 of `.devcontainer/Dockerfile`, which a `v1.10` verifier still refuses, and `v1.8`'s move of the secret scan from betterleaks 2.0.0-rc.7 to rc.8, whose default rules also changed.

### Dev-App repos: the template window

The `v1.10` verifier accepts the `v1.10` dev-App template and a snapshot of the `v1.9` template. Their `devcontainer.json`, the only template file the verifier compares, is identical to the `v1.7` template's: `template/.devcontainer/devcontainer.json` has not changed since `v1.7`. The template's `Dockerfile` changed only in line 1 (1.29) and a header comment. A repo on any of those templates moves its verify pin to `v1.10` with no template change.

## Behaviour changes

- **Legacy gate: every row but `arm` disarms auto-merge, and a failed disarm fails closed** (#709). GitHub does not disarm auto-merge when a writer pushes to an armed PR. Before this release, a candidate PR that was armed and then pushed to had a head that was no longer a candidate, landed in the gate's `plain` row and stayed armed, so a green `architect-review` merged it with no human click. The `plain` row now disarms before it looks up the review, as the `disarm-review` and error rows already did. In all three, a failed disarm posts a `failure` status ("Could not disable auto-merge on PR #N -- failing closed.") and the job exits 1 without looking up the review, because the job's exit code enforces nothing and a `success` posted after a failed disarm would let the armed PR merge. This is a change to the copied gate, so it reaches a repo only when the repo re-copies it.
- **`secrets / scan` runs betterleaks 2.0.0-rc.10**, as above.
- **`verify / verify` and `decide`: one exemption that applies to this repo only** (#707). The rule that refuses any `devcontainer.json` other than `.devcontainer/devcontainer.json` now skips the regular file `template/.devcontainer/devcontainer.json` when the repository is exactly `603-Identity/devcontainers`, in both the verifier (its `verify` and `decide` commands) and `tools/fetch-consumer.sh`. The repository name is `github.repository`, which no caller input sets, so no consuming repo's result changes.

The `decide` and verify reusable workflows otherwise changed only in their `actions/setup-go` pin (v7.0.0 to v7.1.0). No other verifier, `decide`, reusable-workflow or consumer-lint behaviour changed.

## Image changes

The images publish on every push to `main` and reach consumers by digest through Dependabot, independently of this tag. These landed between `v1.9` and `v1.10`:

- **betterleaks 2.0.0-rc.10** (from rc.8, #700), with the default-rule changes above, for the pre-commit hook.
- **tofu 1.13.10** (from 1.13.9, #696), **npm 12.2.3** (from 12.2.2, #697), **CPython 3.15.2 build 20261123** (from build 20261110, #698) and **uv 0.13.9** (from 0.13.8, #699).
- **`/usr/bin/pebble` is removed from the base image's filesystem** (#628). The `ubuntu:26.04` base layer carries the rockcraft `pebble` binary, which is not a dpkg package and which nothing in the images uses; it carried CVE-2026-97054. Its bytes remain in the lower layer (known gaps, below).
- **CVE-2026-97054 is excepted on yq, tofu and tflint** (#628). It is a Go `net/http` HIGH, fixed in Go 1.26.11 and 1.27.4. No yq or tflint release is built with a fixed Go yet. tofu 1.13.10 (#696) is built with Go 1.27.4, so its entry no longer matches the shipped binary and can go at the next renewal. Each entry in `.trivyignore.yaml` covers one binary's path and expires on 2026-12-17, like the earlier exceptions.

## Known gaps (still open)

- **Every Trivy exception expires on 2026-12-17.** A publishing build after that date (a push to `main` or the weekly rebuild) fails the image gate unless the exceptions are renewed after a fresh re-scan or the binaries are fixed upstream. A pull request's gate is differential and fails only on findings the published image lacks. Images already published are unaffected.
- **The removed pebble binary's bytes still ship in the `ubuntu:26.04` lower layer** (threat model). The merged filesystem the scans read no longer has it, and nothing in the images starts it.
- **The image scan does not see the interpreter** (DEVC-D11). Trivy identifies no component under `/opt/devc/python`, and the image's SBOM does not list it.
- **The consumer lint misses one mistake** (#521). It does not warn when a dev-App repo pins a verifier older than dev-App mode. Today the error appears only as a `verify / verify` failure.
- **No ruleset covers a tag named `main`** (#689, recorded in the threat model). A writer here could push one at an old commit of `main` and dispatch that commit's `build.yml`, which had no ref guard on publishing. The control of record is the consumer side: `verify / verify` checks the provenance signed for `refs/heads/main`, so keep it required.
