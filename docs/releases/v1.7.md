This release lets dev-App repos install their pinned Claude Code plugin at every container start. It ships an LF-everywhere `.gitattributes`. The org secret scan works with betterleaks 2.0.0-rc.3 and later. It is also the first release whose verifier accepts the previous release's dev-App template as well as its own.

**Tag:** `v1.7` → `0517df2c0288c8c5d817cc9c286c37975e6399b1` (signed). Pin the reusable workflows to that SHA, never to the tag name: each called workflow checks that it was pinned by SHA.

## Upgrade

The template files at this tag still pin `v1.6`, because a commit cannot pin its own release. Use the SHA above, or copy the template from `e1d4846` (#520), which pins `v1.7`.

### Every consuming repo

1. **Re-point the pins** to `@0517df2c0288c8c5d817cc9c286c37975e6399b1 # v1.7`. Dependabot's `github-actions` ecosystem proposes this as a reviewed PR.
   - `secret-scan.yml`: the scan uses the new git-log path (below). This pin is independent of the others. It also moves the repo's CI scan from betterleaks 2.0.0-rc.1 to rc.7, because the workflow reads `BETTERLEAKS_VERSION` from the Dockerfile at the pinned commit. The default rules changed in between. For example, since rc.3 the default `aws-access-token` rule also reports a lone AWS access key, which `org-aws-access-key-id` already reported, so such a key now shows up as two findings with the same fingerprint. Fingerprints hash the secret value and are the same under both versions, so existing ignore-file entries still match. Review any new finding the first scan reports like any other.
   - `devcontainer-image.yml`: the verifier.
   - Legacy-gate repos only: `devcontainer-bump-decision.yml` in the gate's `decide` job. Keep it on the same SHA as the verify pin, or the consumer lint warns. The gate itself is unchanged apart from that pin, so it does not need re-copying.
2. **Update a betterleaks pre-commit hook**, if the repo has one. The images now ship betterleaks 2.0.0-rc.7 (from rc.1). Since 2.0.0-rc.3 betterleaks has no `--staged`, so a hook running `betterleaks git . --staged` fails. The README's hook entry now pipes `git diff --staged` into `betterleaks stdin --git-diff` (README, "Secret scanning").
3. **Re-run the consumer lint** from a checkout of this repo at `v1.7`: `<checkout>/tools/check-consumer-workflows.sh <your-repo>/.github/workflows`. Its rules are unchanged since `v1.6`, so a repo that passed then should pass now.
4. **Take `template/.gitattributes`** (#504). Copy it to the repo root, or merge its two rules into an existing file. Make the renormalisation commit the PR's first commit, then restore any existing Windows checkout. The commands are in README, "Using an image in a repo", step 5. This step does not depend on the release and can be taken at any time.

### Dev-App repos: the plugin install (#503)

The template's `postStartCommand` now ends with `sh /usr/local/share/devc/plugin-install.sh`. That script installs, at user scope, the plugins the repo's `.claude/settings.json` pins. It fails the start loudly when it cannot install one. Take three changes together, in **one** PR:

- the `devcontainer.json` change, copied from `template/`;
- the verify pin moved to `v1.7` (a `v1.6` verifier rejects the new `postStartCommand`);
- an image bump to any `devcontainer-devapp` or `devcontainer-devapp-tofu` build from after `4158d91`, by tag and digest from the latest *Build images* run.

Under an older image the start fails, because `sh` cannot open the script. Under an older verifier, `verify / verify` fails.

A repo can also stay on the `v1.6` template while it pins `v1.7`: the `v1.7` verifier accepts both (below).

## Behaviour changes

- **The verifier accepts the previous release's dev-App template** (#418 owner decision 5). `devc-verify` now embeds a snapshot of the template the self-pins named when this release was cut, here `v1.6`'s. In dev-App mode, a consumer's `devcontainer.json` may match either that snapshot or the template at the pinned release. Each release accepts its own template and the one before. A repo two releases behind fails `verify / verify` until it catches up.
- **The org secret scan reads git itself** (#449). betterleaks rc.3 and later no longer run git, so `tools/secret-scan.sh` now pipes a full-ancestry `git log -p` into `betterleaks stdin --git-diff`. The git flags are pinned to keep coverage: root commits, each merge parent separately, binary-as-text, no renames or textconv, full ids. The scan still fails closed; a failed or truncated git run is now reported as its own state, `gitfail`. A scanner that cannot start (exit 126 or above) is reported as the scanner's failure, not as `gitfail`. `BETTERLEAKS_FINGERPRINT_HMAC_KEY` is now refused, because it changes the fingerprints the ignore file matches.
- **dev-token accepts GitHub's stateless installation tokens** (#493). The token can now be `ghs_` followed by 36 or more of `[A-Za-z0-9._-]`. The file cap rose from 512 to 2048 bytes. Everything else is unchanged: LF only, a single read, refusal from 60 s before expiry.

## Image changes

The images publish on every push to `main` and reach consumers by digest through Dependabot, independently of this tag. These landed between `v1.6` and `v1.7`:

- **Node 26.13.0** (from 24.22.2, #436) with **npm 12.2.2**. Consuming repos' CI still pins `node-version: 24`, so a container and its CI now differ on Node's major version until each repo moves its pin. npm 12.2.2 bundles a fixed undici, so the image's in-place undici swap is gone (#510). The node image installs `libatomic1`, which Node 26 needs (#450).
- **Base image apt packages are upgraded at build** (#495). Packages that ship inside the `ubuntu:26.04` image itself now receive security fixes from the weekly rebuild too.
- **Tool bumps:** betterleaks 2.0.0-rc.7 (from rc.1), tofu 1.13.9, tflint 0.66.0, yq 4.54.3, uv 0.13.7, zizmor 1.32.0. A repo using the tofu image moves its `tofu_version` in the same PR that takes the new digest.
- **Fewer scan exceptions** (#519). The Trivy allowlist has 8 entries, down from 23 at `v1.6`. The rc.6 bump took it to 36. betterleaks rc.7, built with a newer Go release, then cleared the 26 findings its rc.6 build carried (Go standard library and `golang.org/x/net`), and tflint 0.66.0 scans clean. tofu 1.13.9's checksum file was verified by hand with cosign (#511).

## Known gaps (still open)

- **The consumer lint misses one mistake** (#521). It does not warn when a dev-App repo pins a verifier older than dev-App mode. Today the error appears only as a `verify / verify` failure.
- **Release pages for `v1.5` and `v1.6` are missing** (#486). Those tags have no GitHub Release yet.
