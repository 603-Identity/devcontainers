This release moves the template's Dockerfile to `docker/dockerfile:1.28` and teaches the verifier to accept it. The consumer lint now checks that every pin is a commit on this repo's `main`, and it checks the gate's triggers. Re-pin all three workflows to `v1.5` before moving a repo's `# syntax=` line.

These notes were written on 2026-11-10, after `v1.7`: `v1.5` shipped as a tag only (#486). Known gaps are as of that date.

**Tag:** `v1.5` → `4baf61c7aaacfd30ca5c6feb83cb27ace7953c1c` (signed). Pin the reusable workflows to that SHA, never to the tag name: each called workflow checks that it was pinned by SHA.

## Upgrade, if your repo uses the gate

The template files at this tag still pin `v1.4`, and its Dockerfile is already on 1.28, which the `v1.4` verifier rejects. Do not copy `template/` at this tag. Use the SHA above, or copy the template from `e9a5d73` (#430), which pins `v1.5`.

1. **Re-point all three pins** to `@4baf61c7aaacfd30ca5c6feb83cb27ace7953c1c # v1.5`:
   - `devcontainer-bump-decision.yml`, in the gate's `decide` job (`architect-review-gate.yml`).
   - `verify-devcontainer-image.yml`, in `devcontainer-image.yml`. Keep it on the same SHA as the `decide` pin, or the consumer lint warns.
   - `secret-scan.yml`, in `secret-scan.yml`. Its pin is independent of the other two. The secret scan itself is unchanged since `v1.4`.

   The gate's logic is unchanged since `v1.4`, so it does not need re-copying.
2. **Move the Dockerfile's `# syntax=` line to 1.28**, optionally: `docker/dockerfile:1.28@sha256:bb22d9815c728170f72750f4e5b0d672e06176142e1d602c7e66c050100b7e5b`. The `v1.5` verifier accepts 1.28 and the previous 1.27, so a repo can stay on 1.27 for now. Only move it with or after the re-pin: a `v1.4` verifier rejects 1.28.
3. **Re-run the consumer lint** from a checkout of this repo at `v1.5`: `<checkout>/tools/check-consumer-workflows.sh <your-repo>/.github/workflows`. It now rejects more (below), so a repo that passed under `v1.4` can fail. It also needs `git` and network access to github.com now, for the pin check. Exit 3 means the pins could not be checked; never read it as a pass.

## Behaviour changes

- **The verifier accepts dockerfile 1.28** (#422). `devc-verify` vendors BuildKit 0.34.1, whose frontend is 1.28. A consumer's `# syntax=` line may be 1.28 (current) or 1.27 (previous).

## Consumer lint (`tools/check-consumer-workflows.sh`)

- **Every pin must be on this repo's `main`** (#365, closes #234). Each distinct verify, decide and secret-scan pin must be on the first-parent line of `603-Identity/devcontainers` `main`, and its `# vX.Y` comment must name a tag that peels to it. Before, a pin of the right shape could name any commit in the fork network. The lint clones `main` from a fixed URL, with no token. A failed clone exits 3, as does `--no-provenance`, the offline mode.
- **The gate's triggers are checked** (#341). `on:` must be a mapping with `pull_request` (opened, synchronize, reopened), `issue_comment` (created) and `pull_request_review` (submitted, edited, dismissed), with nothing but `types:` under each. **A gate copied before `v1.4` now fails**: re-copy it from the template.
- Every finding and warning prints a control character as `?`, so a workflow file name with a newline cannot forge a log line (#334).
- A non-canonical `code_paths` entry no longer also draws a `pattern matches none` warning for the arms that cover it (#335).

## This repo only (no action for consumers)

- The publish gate diffs against the last successful publish, not the push's own `before`, so an image change left unpublished by a cancelled or failed run goes out on the next push (#381).
- While the betterleaks pin is a release candidate, `bump-binaries` proposes only GA releases and release candidates of the pin's own `X.Y.Z`. A later line's release candidate no longer keeps the pin on the release-candidate track past GA (#304). A yq release without a SHA-256 line now reports an error instead of exiting silently (#325).

## Images

Images publish on merges to `main` that change an image, and on the weekly schedule, not on tags. Take them through Dependabot's digest bumps as usual. Since `v1.4`:

- **The Trivy gate is green again** (#419). It had failed every image PR and the weekly rebuild. The fix bumped the `ubuntu:26.04` digest and the tools below, and renewed 23 exceptions for findings with no upstream fix, all expiring on 2026-12-01.
- **Tool bumps:** gh 2.103.2, tofu 1.13.2, tflint 0.65.0, zizmor 1.31.1, uv 0.13.6, Node 24.22.2 with npm 12.2.1. The image Dockerfiles moved to dockerfile 1.28.
- **uv 0.13 makes Python 3.15 its default** for `uv python install` (#421). uv still prefers an installed interpreter, so `uv venv` in the image picks the system Python 3.14. The `devc-cache` volume may re-download once, because uv's cache format changed.
- A repo using the tofu image moves its `tofu_version` in the same PR that takes the new digest.
